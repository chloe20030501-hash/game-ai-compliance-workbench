# 游戏 AI 功能上线合规工作台

一个面向法务求职展示与学习训练的前端原型。当前版本以“AI 角色陪伴中的跨对话长期记忆”为场景，帮助产品、算法、后端、数据安全和法务在进入法律判断前，先把产品事实问清楚。

> 当前版本是事实调查工具，不自动给出“合规 / 不合规”结论，也不代表任何公司的内部流程或法律意见。

## 它解决什么问题

AI 功能上线审查经常不是缺少法条，而是事实没有被问完整：记忆是否默认开启、来自哪些对话、保存原文还是摘要、是否用于模型训练、用户删除后哪些副本仍然存在、第三方供应商是否能自行留存数据等。

本原型把这些问题整理成可填写的业务问卷，并将答案转化为：

- 已确认的产品事实；
- 仍需追问的事项；
- 初步关注点；
- 建议参与确认的团队；
- 可下载的事实确认摘要表。

## 当前场景与四组问题

1. **基本场景**：上线地区、目标用户年龄、AI 角色陪伴属性、跨对话记忆范围。
2. **记忆产生**：开启方式、生成触发、信息来源、敏感信息处理、保存形式。
3. **数据用途**：未来回复、模型训练或微调、其他用途、保存期限。
4. **用户控制**：查看、修改、逐条删除、全部清除、关闭功能，以及后台和备份中的实际效果。

## 工作流程

```text
业务提交功能
→ 相关团队填写或确认产品事实
→ 工具整理已确认事实与待确认事项
→ 法务结合适用市场和数据流进行人工判断
→ 产品与研发补充事实或调整方案
→ 形成结论、上线条件和留痕材料
```

## 主要设计选择

- 允许选择“暂不清楚”，因为真实审查的第一步往往是暴露事实缺口，而不是强迫填写确定答案。
- 将“个性化回复”和“模型训练”分开，避免把不同数据用途混为一谈。
- 将确认对象按产品、算法、后端、安全、数据和法务等角色组织，便于跨团队协作。
- 输出关注点但不输出自动法律结论，保留人工复核和法律判断的位置。
- 当前所有输入仅保存在浏览器页面，不上传服务器。

## 如何运行

项目是单文件静态网页，无需安装依赖。

1. 下载或克隆本仓库；
2. 直接打开 `dist/index.html`；
3. 或将 `dist` 目录部署到任意静态网页服务。

## 作品边界

- 所有业务场景均为教学假设，不声称来自任何公司的内部制度或数据。
- 自动生成的关注点用于辅助发现问题，不替代对产品文档、技术实现和适用法律的核验。
- 当前版本未完成法规自动匹配、风险定级、审批流、账号系统和企业内网集成。
- 这是 AI 辅助开发项目。作者负责问题选择、需求定义、法律框架、产品取舍、测试与结果判断，代码实现由 AI 工具协助完成。

## 后续路线

下一步不会一次性扩展为大型系统，而会继续完成小而完整的纵向切片：

1. 第三方 AI 供应商“数据使用与模型训练”条款核查；
2. 一页审查流程、条款修改样例和审查记录；
3. 使用模拟案例测试并记录失败与修改；
4. 再考虑接入风险清单、上线检查和法规知识库。

## 面试中的三句话

1. 我发现 AI 合规审查在进入法条判断前，首先需要解决产品事实分散、跨团队语言不一致的问题。
2. 因此我选取 AI 角色长期记忆这一窄场景，把事实调查拆成四组问题，并让工具输出待确认事项和责任团队，而不是冒充自动法律结论。
3. 下一步我会用第三方 AI 供应商合同条款测试同一套数据用途判断，并记录工具遗漏和迭代过程。
